## Instructions

Move `ruby_llm` from the released 2.0 line to the **2.2 line, pinned by git
ref**. Read this paragraph before starting, because the pin is unusual: 2.2 is
unreleased. RubyGems tops out at 2.1.1 and the gem's `version.rb` still reads
`2.1.1` on main, while main carries the whole 2.2 feature set. Taking this ref
means your `bundle install` and your image builds now need git access to
`github.com/crmne/ruby_llm`, and no release tag protects a ref. When a released
2.2 gem exists it supersedes this entry: use `gem "ruby_llm", "~> 2.2"` instead
and skip step 1's ref.

1. In `Gemfile`, replace `gem "ruby_llm", "~> 2.0"` with:

   ```ruby
   gem "ruby_llm", github: "crmne/ruby_llm", ref: "1feba97feb8ab28655a0128c2885721c05294b84"
   ```

   Run `bundle install`. Expect three lockfile changes: a `GIT` stanza for
   `ruby_llm` at that revision, the spec reading `ruby_llm (2.1.1)`, and
   `event_stream_parser` dropping out, because the gem no longer depends on it.
   `DEPENDENCIES` becomes `ruby_llm!` and the `CHECKSUMS` entry loses its
   `sha256=`, which is normal for a git source.

2. In `config/initializers/ruby_llm.rb`, fix the `chat.ruby_llm` subscriber's
   token logging. If it reads anything like
   `payload[:total_tokens] || payload[:tokens]`, that line has been logging an
   object address rather than a count: `:total_tokens` has never been a
   notification payload key in any 2.x version (the name exists only inside
   provider wire parsing), so the first branch was always `nil` and the second
   interpolated a `RubyLLM::Tokens` value object. Read the buckets instead:

   ```ruby
   counts = (payload[:response_tokens] || payload[:tokens]).then { |t| t.respond_to?(:to_h) ? t.to_h : {} }
   ```

   and render `counts` as `bucket=count` pairs. Prefer `:response_tokens`: the
   gem seeds the payload with an empty `Tokens` and fills that key once the
   completion returns. `Tokens#to_h` is already compacted, so a bucket the
   provider did not report is absent rather than zero; log something like
   `unknown` when the hash is empty.

3. If your app asserts `RubyLLM::VERSION` anywhere, that assertion is now
   wrong twice over: it reads `2.1.1` at this pin, and the version string
   cannot tell this pin apart from the published 2.1.1 gem. Assert the revision
   in `Gemfile.lock` instead — see `test/initializers/ruby_llm_test.rb` in the
   template for the shape — so that moving the ref is a deliberate act.

4. Replace the app's `docs/modules/ruby_llm.md` with the template's copy. It
   gained three facts worth reading rather than diffing: that persistence stays
   an opt-in and `ruby_llm:install` would overwrite your initializer and write
   an `ApplicationAgent` that raises on eager load without a `Chat` model; that
   the gem claims `app/tools` as its convention directory, which collides with
   a WebMCP registry kept there; and that code execution exists, is unarmed,
   and can be switched on three different ways.

5. Do **not** run `bin/rails g ruby_llm:upgrade` or `ruby_llm:install` to get
   this. The upgrade generator carries schema changes for apps that persist
   chats, and on a template-shaped app it also strips
   `has_many_attached :attachments` and injects
   `config.broadcast_messages = true`, which is wrong for an app that renders
   through Inertia rather than Turbo. An app that does persist chats should read
   the gem's own upgrade guide and apply the schema change deliberately,
   keeping its migrations dialect-neutral if it supports more than one adapter.

## Verify

- `bin/rails test test/initializers/ruby_llm_test.rb` passes, including the
  revision assertion.
- `bin/rails runner 'puts RubyLLM::VERSION'` prints `2.1.1` — that is correct
  at this pin, not a failed upgrade.
- `bundle list | grep ruby_llm` reports the git ref.
- A completion logs real counts: the `[ruby_llm] chat …` line shows
  `tokens=input_tokens=… output_tokens=…`, never a `#<RubyLLM::Tokens…>`
  address, and `tokens=unknown` when no usage was reported.
- `bin/rails test && npm run check && bin/rubocop && bin/brakeman --no-pager && bin/bundler-audit`
  all pass.
